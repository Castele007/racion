# Рацион

«Рацион» составляет семейное меню на семь дней для жителей Оренбурга. В приложении 108 рецептов домашней кухни с количеством ингредиентов и пошаговыми инструкциями. Сайт работает без регистрации и хранит меню, исключения, бюджет, выбранный магазин и отметки о покупках в браузере.

## Запуск

Для сайта достаточно Python 3.12. Устанавливать зависимости для работы приложения и сборщиков не нужно.

```bash
python3 -m http.server 4173 --bind 127.0.0.1 --directory site
```

Откройте `http://127.0.0.1:4173`. Укажите число человек, недельный бюджет и продукты, которые нужно исключить. Нажмите **Составить меню**. У каждого блюда есть рецепт и список подходящих замен. Список покупок пересчитывается после составления меню и после каждой замены.

## Корзина и бюджет

- Порции масштабируются от базового рецепта. Потребность по одному ингредиенту суммируется по всему меню, после чего подбирается комбинация целых упаковок с наименьшей стоимостью.
- Корзины магазинов считаются отдельно. В расчёт входят товары в наличии с обычной ценой и действующие акции с подтверждёнными датами, которые доступны без дополнительных условий. Цены по карте, при покупке нескольких упаковок или при выполнении других условий можно увидеть в сведениях о товаре. Доставка и сервисные сборы считаются отдельно магазином.
- При достаточном покрытии планировщик ищет разнообразное меню в пределах бюджета. Поиск перебирает и улучшает несколько вариантов. Остаток или превышение бюджета отображается после оценки всей корзины. Для неполной корзины известная сумма показана отдельно. Если исключения оставляют меньше семи блюд одного типа, план может содержать повторы.
- При сбое сборщик сохраняет последнюю подтверждённую цену и её дату. Приложение помечает такие цены как устаревшие. Данные старше 12 часов тоже считаются устаревшими. Полная актуальная корзина в сравнении имеет приоритет перед архивным расчётом.

## Подключение и обновление цен

Для каждой сети используется свой модуль в `collectors/`. Общий код проверяет HTTPS-домен, правила `robots.txt` и интервал запросов. Переходы на другие домены допускаются только внутри списка официальных доменов соответствующей сети. Сборщик прекращает работу с источником при отказе в доступе, ограничении частоты или сетевом сбое, учитывает `Retry-After` и сохраняет последнее рабочее состояние в JSON.

Диагностика без записи данных и обычное обновление запускаются из корня репозитория.

```bash
python3 -m collectors.update --probe
python3 -m collectors.update
python3 -m collectors.update --sources catalog-sources.local.json
```

Где доступен источник с разрешением на автоматическое использование, добавьте его в переменную репозитория `CATALOG_SOURCES_JSON` в **Settings → Secrets and variables → Actions → Variables**. Для локального запуска можно передать тот же JSON через флаг `--sources`. Конфигурация содержит только публичные адреса и сведения об источниках.

Верхний уровень JSON содержит настройки по идентификаторам `pyaterochka`, `magnit`, `lenta`, `perekrestok` и `metro`. Присутствие сети в файле означает, что владелец проекта проверил право повторного использования цен, разрешённые пути, соответствие каналу продажи и требования к частоте обновлений. Для каждой настроенной сети обязательны следующие поля.

| Поле | Содержание |
| --- | --- |
| `authorization` | Объект с `url` официальных условий или документации, `note` с основанием для автоматического использования, `verifiedAt` в ISO 8601 с часовым поясом. |
| `location` | `city` со значением `Оренбург`, официальный `id` точки, её `address` и `channel` из `pickup`, `in-store` или `delivery`. На одну сеть используется одна точка и один канал продажи. |
| `format` | `regional-json` для документированной региональной выгрузки или `json-ld` для доступных карточек товаров с документированной структурой цены. |

### Региональная выгрузка JSON

Настройка с `format: "regional-json"` содержит `url` официального фида. Обработчик ожидает в ответе `location` и массив `products`. Город, адрес, ID точки и канал должны совпасть с настройками.

| Поля предложения | Формат |
| --- | --- |
| `id`, `ingredientId`, `name` | Уникальный ID предложения, ключ из `site/data/ingredients.json`, название товара. |
| `packSize`, `unit` | Целое количество в упаковке в граммах (`g`), миллилитрах (`ml`) или штуках (`pcs`). |
| `price`, `currency` | Точная цена одной упаковки, например целое число или строка с двумя десятичными знаками. Валюта `RUB`. |
| `available`, `sourceUrl`, `updatedAt` | Булево наличие, официальный HTTPS-адрес карточки и дата цены ISO 8601 с часовым поясом. |
| `terms` | Объект с `kind` из `regular`, `public`, `conditional`. Для `public` обязательны `startsAt` и `endsAt` с часовым поясом. Для `conditional` укажите описание в `note`. Промоцену и обычную цену можно передать двумя предложениями с разными ID. |

### Карточки товаров с JSON-LD

Для `format: "json-ld"` укажите `priceMode: "documented-single-unit"` и массив `products`. Каждая запись содержит `url`, `id` (SKU магазина), `ingredientId`, `packSize` и `unit`. Страница должна подтверждать SKU, вес упаковки, наличие, цену в рублях и точку продажи через `Product`, `Offer` и `availableAtOrFrom`. Условия акции без подтверждённых дат или с дополнительными требованиями помечаются как условные. Поддержка другого официального формата требует отдельного адаптера и проверки.

## GitHub Actions и Pages

В **Settings → Pages → Build and deployment** выберите **GitHub Actions**. После появления проекта в `main` workflow `Update prices and publish Pages` публикует только папку `site/`. Пути к файлам работают и при публикации в подкаталоге репозитория.

Запуск по расписанию `17 */3 * * *` обновляет `site/data/prices.json` каждые три часа, сохраняет снимок в `main` и публикует сайт в том же workflow. Ручной запуск доступен в **Actions → Update prices and publish Pages → Run workflow**. Для обновления JSON используется штатный `GITHUB_TOKEN` с доступом на запись в задании сборщика. Для публикации Pages выданы отдельные разрешения. При введении защиты ветки настройте право записи для задания обновления.

## Тесты

```bash
node --test tests/planner.test.mjs
python3 -m unittest discover -s tests
```

Чтобы повторить браузерные сценарии, установите Playwright во временную папку и запустите тесты. Приложение не использует Node.js или Playwright при обычной работе.

```bash
racion_test_dir="$(mktemp -d)"
npm install --prefix "$racion_test_dir" --no-audit --no-fund playwright@1.62.1
"$racion_test_dir/node_modules/.bin/playwright" install chromium
NODE_PATH="$racion_test_dir/node_modules" node --test tests/browser.test.mjs
```

Автоматические проверки запускаются при изменениях в `main` и открытии Pull Request. Браузерные сценарии проверяют семь дней меню, расчёт порций, исключения, замену блюд, сохранение настроек и отметок, отображение неполной и архивной корзины и ширину интерфейса на смартфоне. Лицензии локальных шрифтов Manrope и Lora лежат в `site/assets/`.
